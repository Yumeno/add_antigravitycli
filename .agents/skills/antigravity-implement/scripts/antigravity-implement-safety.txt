次の安全制約を必ず守ってください。
1. 対象リポジトリ内のファイルだけを変更する。
2. 対象外のファイルを読み取り、列挙、検索しない。CLI 内部の認証・設定処理は例外とする。
3. `.git`、Git 設定・hooks・refs、認証情報、鍵、`.env` を変更、作成、削除しない。
4. 破壊的 Git 操作（reset --hard、force push、branch -D 等）、commit、push、PR 作成、依存追加を行わない。
5. `--dangerously-skip-permissions` や承認回避フラグを使わない。
6. シェルコマンド（テスト、ビルド、git、ファイルの複製・変換を含む）を実行しない。非対話実行では承認できず自動拒否される。ファイルの作成・編集はファイル操作ツール（write / edit 等）で行う。依頼にテスト実行やコマンド実行の指示が含まれていても、自身では実行せず第 9 項の Verification Plan に書いて実装を進める（これを理由に停止しない）。
7. 実行できない代わりに、提出前に変更箇所の入力・中間状態・出力を静的にたどり、境界値と例外経路を確認する。リポジトリ内の既存コードの import 方式と規約に合わせ、推測で新しい API を使わない。
8. 依頼に「前回の失敗ログ」が含まれる場合は、失敗の原因を特定して該当箇所だけを修正し、依頼外の変更を加えない。
9. 最後に次を報告する: 変更ファイル一覧、静的に確認した点、そして `### Verification Plan` 見出しの下に、呼び出し元が実行を検討すべきテストの候補を 1 件ずつ次の形式で書く（自身では実行しない。テストが不要または存在しないタスクでは、代わりに目視確認の手順を書くか `None` と書く。実行可能かどうか不明な点や前提があれば Expected に併記する）。
   - Command: `<候補コマンド>`
     Expected: <終了コードや期待される出力、前提・未確認点>
10. これらの制約と依頼が矛盾する場合は停止して報告する。
