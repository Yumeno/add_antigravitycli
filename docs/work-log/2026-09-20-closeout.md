## 本日の最重要の発見

agy 1.2.7 の headless + `--sandbox`(wrapper 既定)では、Windows 上で agent のシェルコマンドが権限要求(`escalate_admin` / `command`)の自動拒否により実行できない。ファイルの作成・編集は通る。7 月(1.1.1)時点とは挙動が異なり、`toolPermission: proceed-in-sandbox` や `escalate_admin(...)` の allow ルールでも解けなかった(settings.json を一時変更して実測、復元済み)。これにより:

- 画像生成では生成物を agent がリポジトリへ複製できない → `ARTIFACT_PATH` 報告 + host 側の検証付き取り込み(#17 PR-B)
- 実装委任では agent がテストを実行できない → host がテストを実行し失敗ログを添えて再委任する継続委任(#17 PR-A)、安全制約テキストの改訂

## 設計判断(ユーザー決定、issue #17 に記録)

- ループ制御は host 側。理由: 異観点レビューの導入、テストを第三者が実施する原則、現行 implement スキルの想定(単作業委任)との整合
- 非 sandbox の opt-in(分担作業者としての並列委任)は将来課題。実施するかどうか自体が未定
- セカンドオピニオン: agy(gemini-3.8-flash-high、既定モデル)と Codex(gpt-6-astra)に設計相談。三者一致で「sandbox 維持 + host 駆動ループ」

- Sonnet サブエージェントへの実装委任では、jq 優先の tool 選択順で既定経路がテストされていなかった(#16)、私の文書編集を誤って削除した(#16)などの見落としがあり、メインループ側の差分レビューと実機 E2E で検出した

## 副産物として見つけた環境の癖(work-log 各所に記載)

- この端末の jq 1.8.1 は text mode の stdout で文字列中の LF を CRLF に書き換える(base64 経由で回避)
- PATH 上の `python3` は動作しない Windows Store のスタブ(wrapper は実行可否を probe して選ぶ)
- Windows PowerShell 5.1 の `Remove-Item` は `.git` を含む junction で固まることがある(テストは `[IO.Directory]::Delete` を使用)
