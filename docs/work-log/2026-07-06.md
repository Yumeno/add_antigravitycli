## 実装

### Agent Skills

Codex用 `.agents/skills/` とClaude Code用 `.claude/skills/` に以下を追加した。

- `ask-antigravity`
- `ask-antigravity-with-context`
- `antigravity-implement`
- `list-antigravity-models`
- `set-antigravity-model`

質問系と実装系を分離し、実装委任は明示起動、clean tree、Git snapshot、実行後の独立検収を必須とした。

### wrapper・検収

PowerShell 5.1版とbash版を実装した。

- `scripts/antigravity-wrapper.ps1` / `.sh`
- `scripts/antigravity-implement.ps1` / `.sh`
- `scripts/antigravity-verify.ps1` / `.sh`

主な仕様:

- promptをstdinで`agy --print`へ渡す
- `--sandbox`を値なしboolean flagとして常時有効化
- `--new-project`と`--add-dir`でsession workspaceを明示
- 親processと`agy --print-timeout`の二重timeout
- wrapper失敗をsentinelでモデル回答と区別
- モデル設定の優先順位を「明示引数、環境変数、設定ファイル、CLI既定」とする
- 実装委任前後でHEAD、branch、status、保護対象を比較
- 自動rollbackは行わない

### 複数・異種media

mediaを元pathのまま広く公開せず、wrapper所有の一時workspaceへcopyする方式を実装した。

- PowerShell
  - 単一: `-Attachment`
  - 複数: `-AttachmentList`。UTF-8、1行1絶対path
- bash
  - `--attachment`を順序どおり反復

manifestには以下を記録する。

- 指定順
- 元ファイル名
- staging path
- MIME
- byte数
- `probe-verified` / `experimental`

安全対策:

- directoryを拒否
- symlink / reparse pointを拒否
- magic bytesまたはOSのMIME判定で認識できない形式を拒否
- staging時は検出MIMEに対応したcanonical拡張子を使う
- 元mediaを変更しない
- 終了・失敗時にwrapper所有の一時ファイルだけを削除
- silent truncationや暗黙の形式変換を行わない

任意バイナリ対応ではなく、media allowlist方式とした。

## 実機probe

### テキスト非対話実行

`agy --print --print-timeout 5s --sandbox`へstdinでpromptを渡し、`OK`、exit code 0を確認した。

### workspace内PNG

公式Antigravity SDK同梱のGoogleロゴPNGをpath指定し、画像内文字`Google`を認識した。

### JPEG + WAV

Windows標準のwallpaper JPEGとアラームWAVを同一turnへ渡した。

- JPEGの青い立体的な視覚要素を説明
- WAVに人の発話がなく、電子的なアラーム音であることを説明
- 指定順を保持

### MP3 + MP4

`C:\ffmpeg\bin\ffmpeg.exe`で既知内容のmediaを生成した。

- MP3: 2秒の440Hz正弦波
- MP4: test pattern映像 + 880Hz正弦波音声

Antigravityは440Hz、880Hz、test pattern、発話なしをそれぞれ認識し、指定順に回答した。

## 実装中に検出・修正した問題

- `--sandbox`へ`read-only` / `workspace-write`を渡していたCLI契約不整合
- PowerShell検収がGitのCRLF警告をfailureとして扱う問題
- Antigravityが既定project情報を探索するため、working directoryだけではworkspaceを限定できない問題
- media manifestの総byte数をPowerShellのordered dictionaryから集計できない問題
- media形式検証失敗時に一時directoryが残る問題
- bash manifestで特殊なファイル名が行構造へ影響する問題
- `.gitattributes`の`working-tree-encoding=UTF-8-BOM`でGit stageが失敗する問題

PowerShellのUTF-8 BOMはファイル実体で保持し、Git変換を避けるため以下を使用する。

```gitattributes
*.ps1 -text
*.psm1 -text
```
